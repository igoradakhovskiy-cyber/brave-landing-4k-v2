# BRAVE CAPITAL — лендинг «4 фінансові компетенції»

Посадкова сторінка для людей з добрим доходом в Україні та українців у Європі. Шлях відвідувача:
1. Оцінка 4 компетенцій — квіз на 10 питань.
2. Заявка.
3. Менеджер уточнює запит і час.
4. Безкоштовний розбір ситуації з радником.

Сайт: https://igoradakhovskiy-cyber.github.io/brave-landing-4k/

Один файл `index.html` (стилі й скрипти всередині) і папка `assets/`: шрифти Geologica та Onest (OFL), intl-tel-input, логотипи, фото. Зовнішніх залежностей немає, крім Meta Pixel і сервісів визначення країни за IP.

## Підключення CRM (вебхук)

Логіка відправки вже є. Потрібно лише вставити URL вебхука у змінну на початку головного скрипту в `index.html`:

```js
var SUBMIT_URL = "";   // ← сюди URL вебхука CRM
```

Поки рядок порожній, заявка пишеться лише в консоль браузера (`[lead → CRM]`) і в `dataLayer`. Подія `Lead` у Meta Pixel іде в будь-якому разі.

**Як відправляється.** Кожна форма на сторінці шле `POST` на `SUBMIT_URL` з заголовком `Content-Type: application/json`. Тіло запиту — один JSON-об'єкт. Форм на сторінці три, формат у всіх однаковий:
- під результатом квізу;
- модальне вікно, яке відкривають кнопки «Записатися на розбір»;
- форма внизу сторінки.

**CORS.** Запит іде з браузера з домену `igoradakhovskiy-cyber.github.io`, тож браузер спершу надсилає `OPTIONS`. Вебхук має відповідати на нього заголовками:
- `Access-Control-Allow-Origin` (домен сайту або `*`);
- `Access-Control-Allow-Methods: POST, OPTIONS`;
- `Access-Control-Allow-Headers: Content-Type`.

Якщо CRM так не вміє, поставте між сайтом і CRM проміжний сервіс: Make, n8n, Zapier або Cloudflare Worker.

**Після відправки.** Людина бачить подяку навіть тоді, коли вебхук не відповів: помилки мережі не показуються, щоб не втрачати довіру. Перевіряйте, чи доходять заявки, з боку CRM.

### Поля заявки

| Поле | Що це |
|---|---|
| `name` | Ім'я, як людина просить до неї звертатися |
| `phone` | Телефон у форматі E.164, напр. `+380501234567` (перевірений intl-tel-input) |
| `phone_country` | Країна номера, ISO-2: `ua`, `pl`, `de`… |
| `channel` | Де зручніше: `telegram`, `whatsapp`, `viber`, `call` |
| `time` | Лише для `call`: `morning`, `day`, `evening` або `null` |
| `source` | Звідки заявка: `quiz_book` — форма під результатом квізу; `header`, `hero`, `free`, `sticky` — кнопки, що відкривають модальне вікно; `final` — форма внизу |
| `lead_tag` | `quiz` — людина пройшла оцінку, `direct` — ні |
| `comment` | **Готовий текст для поля «коментар» у CRM**: джерело, канал зв'язку, рівні компетенцій, цілі, що обговорити на розборі, резюме |
| `quiz` | Об'єкт з результатом оцінки або `null`, якщо людина її не проходила (див. нижче) |
| `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `fbclid` | З адреси сторінки, якщо є, інакше `null` |
| `page`, `ts` | Шлях сторінки і час заявки (ISO, UTC) |
| `event_id` | Унікальний ID заявки. Той самий ID іде в Meta Pixel як `eventID` події `Lead` — знадобиться для дедуплікації, коли підключать Conversions API |

Вміст `quiz`:

| Поле | Що це |
|---|---|
| `answers` | Відповіді: `q1`…`q10` → `{question, answer, id}`. У `q10` можна обрати дві цілі, тому `id` там масив |
| `levels` | Рівень кожної компетенції словами: «Сильна сторона», «Є база», «Зона росту» |
| `scores_hidden` | Приховані бали 0–100 по компетенціях (`earn`, `spend`, `save`, `inv`). Людина їх не бачить |
| `skews`, `weakest` | Тип перекосу по кожній компетенції і найслабша компетенція — для кваліфікації |
| `story` | Яку історію клієнта людина побачила в результаті |
| `summary` | Резюме, яке людина бачила на екрані |
| `help` | Три пункти «Як радник BRAVE допоможе» |
| `agenda` | Три пункти «Що обговорити на розборі»: `{title, detail}` |

### Як перевірити

1. Вставте URL у `SUBMIT_URL` і відкрийте сторінку з `?test=it`: одразу з'явиться результат квізу для тестового профілю.
2. Заповніть форму під результатом і відправте.
3. Заявка має з'явитися в CRM. Той самий об'єкт видно в консолі браузера після `[lead → CRM]`.

Тестові профілі: `?test=sasha|it|family|dmytro|kyrylo|strong`.

Для тесту без бойового пікселя відкрийте сторінку локально (`localhost`). Там Meta Pixel вимкнений, увімкнути можна через `?pixel=1`. На опублікованому сайті тестова заявка піде в Meta як справжній `Lead`.

## Аналітика

Meta Pixel `1669140901889164` вантажиться одразу в усіх відвідувачів. Cookie-банера немає.

| Подія | Коли |
|---|---|
| `PageView` | Завантаження сторінки |
| `Lead` (стандартна) | Відправка будь-якої форми. Параметри: `content_name` = `source`, `eventID` = `event_id` заявки |
| `quiz_start`, `quiz_step`, `quiz_complete` (custom) | Воронка квізу |
| `lead_form_open`, `cta_click`, `faq_open` (custom) | Відкриття форми, кліки по кнопках, відкриття питань FAQ |

**У Meta не йде нічого фінансового:** ні відповіді квізу, ні рівні, ні бали. Усі події також пишуться в `dataLayer`.

## Режими перегляду

| Адреса | Що показує |
|---|---|
| `/` | Основна версія |
| `/?test=it` (і інші профілі) | Одразу результат квізу для тестового профілю |
| `/?review=1` | Помаранчевою рамкою підсвічено тексти, які ще треба підтвердити |
